# 電気通信事業の届出：下書き

StudyReel の「勉強仲間」（スタンプ、勉強状況、写真の共有）は、決まったグループの中で利用者どうしのデータを届けるので、「他人の通信の媒介」として届出が要る前提で進める。
**勉強仲間を入れた版を App Store に出す前に届出を済ませる。**

> これは下書きです。様式と添付書類は、提出のときに総務省の「電気通信事業一元受付ポータル」と近畿総合通信局の最新の手引きで確かめてください。迷うところは、近畿総合通信局の電気通信事業課に電話で聞くのが早いです。

## 提出の記録

| 項目 | 内容 |
| --- | --- |
| 提出日 | 2026-10-21（e-Gov 電子申請） |
| 到達番号 | 1812026000079730 |
| 提出先 | 近畿総合通信局 |
| 様式 | 様式第8、様式第4、ネットワーク構成図（様式第3） |
| 事業開始日 | 2026-10-21 |
| 国際の欄 | 全世界（インターネットを通じて提供） |

e-Gov で入力するときに気づいたこと：役務の説明は英字を使わない（全角の英字でもはじかれた）。住所のハイフンは Mac の「−」が通らないので「番地」で書く。

## 書き方の方針：これから作るアプリにも使えるように広めに書く

- 届出の番号（届出番号）は、届出者（人）に付く。ほかのアプリで同じ種類のサービスをするときも、届出番号はそのまま使う
- ただし、届出書に書いた内容（提供する役務、設備の概要、利用する他社の設備など）が変わるときは **変更届出** が要る
- そこで今回は、StudyReel の今の機能だけでなく、**「スマートフォン用アプリでの利用者間のメッセージ・画像・データのやり取り」** として広めに書く。あとでチャット（文字のメッセージ）を足しても、役務の種類が変わらないようにしておく
- クラウドは今は Apple の CloudKit だけ。別のクラウド（Firebase や Supabase など）を使うアプリを作るときは、変更届出が要る見込み

## 1. 届出書に書くこと（様式：電気通信事業届出書）

| 項目 | 書く内容（案） |
| --- | --- |
| 届出者の氏名・住所 | 【氏名】、【住所】（住民票のとおり）。屋号を書く欄があれば「Enludus」 |
| 連絡先 | 【電話番号】、contact@enludus.com |
| 業務区域 | 全国 |
| 電気通信設備の概要 | 自ら電気通信回線設備は設置しない。利用者の端末で動くアプリケーションと、他者（Apple Inc.）のクラウドサービス（iCloud / CloudKit）を利用する。別紙「ネットワーク構成図」のとおり |
| 提供する電気通信役務 | 下の「役務の説明」 |
| 他の電気通信事業者の設備の利用 | Apple Inc.（iCloud / CloudKit） ※ Apple が届出・登録している事業者かどうかは書かなくてよいか、窓口で確認 |
| 事業開始の予定日 | 【勉強仲間を入れた版を出す予定日】 |

### 役務の説明（このまま使える文）

> スマートフォン用アプリケーション（iOS 向け学習記録アプリ「StudyReel」ほか、届出者が提供するアプリケーション）において、利用者が招待・承認した特定の利用者の間で、メッセージ（定型の応援スタンプおよび文字）、画像、学習状況等のデータを送受信・共有する機能を、インターネットを通じて提供する。
> 通信は Apple Inc. のクラウドサービス（iCloud / CloudKit）を介して行い、届出者は電気通信回線設備および通信を媒介するサーバーを設置しない。データは利用者の Apple アカウントの iCloud に保存され、届出者は通信の内容を閲覧しない。利用料金は無料（アプリ内の有料プランで、参加できるグループ数が増える）。

ポータルで役務の種類を選ぶ欄があれば、「インターネット関連サービス」のうち、利用者間のメッセージの媒介にあたるもの（例：「電子メール」ではなく「その他のメッセージ媒介」など）を選ぶ。どれを選ぶかは窓口で確認する。

## 2. 別紙：ネットワーク構成図

`network.pdf`（元は `network.html`）。A4 横1枚。
利用者A ⇄ インターネット ⇄ Apple iCloud（CloudKit） ⇄ インターネット ⇄ 利用者B と、媒介する通信の内容、届出者が設備を設置しないことを書いてある。
【氏名】のところを書き換えてから印刷する（`network.html` の `【氏名】` を直して、ブラウザで PDF に保存）。

## 3. 添付書類（個人で出すとき）

- 届出書
- ネットワーク構成図（別紙）
- 本人確認の書類：調べた範囲では「住民票の写し（3か月以内、マイナンバーなし）」。電子申請（gBizID など）で出すときに要るかどうかも含めて、手引きで確かめる

## 4. 出し方

- 提出先：近畿総合通信局（大阪府に住んでいる場合）
- 方法：電気通信事業一元受付ポータルから電子申請、または郵送・持参
- 手数料：なし
- 期間：受け付けられてから、届出番号（例：A-XX-XXXXX）が届くまで1〜2週間ほど

## 5. 届出のあとに守ること（主なもの）

- **通信の秘密を守る**：グループの中身は見ない。今のつくり（開発者は共有データを見られない）のままにする。見るのは、利用者が自分で送った通報の中身だけ
- **利用者への説明**：プライバシーポリシーに、共有される項目、通報で受け取るもの、保存の期間を書く（company-web の StudyReel のプライバシーポリシー）
- **変更届出**：住所・氏名、役務、設備の概要、使うクラウドが変わったとき。新しいアプリが同じ「アプリ＋CloudKit で利用者間のやり取り」なら、役務の説明に「ほか、届出者が提供するアプリケーション」と書いてあるので変わらない見込み。ここは窓口で確認する
- **やめるとき**：休止・廃止の届出

## 6. 窓口で聞いておくとよいこと

1. 役務の説明を「StudyReel ほか、届出者が提供するアプリケーション」と書けば、今後同じ形のアプリを出すときに変更届出は要らないか
2. 役務の種類の選び方（スタンプ・画像・文字のメッセージ）
3. 利用する他社の設備（Apple の CloudKit）の書き方
4. 個人で電子申請するときの本人確認の書類
