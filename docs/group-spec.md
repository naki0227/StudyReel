# グループ機能 仕様案（たたき台）

YPT やスタディプラスを併用しなくても、StudyReel だけで「仲間と一緒に勉強している感じ」が持てるようにする。
録画中はアプリを開いたままにする必要があるので、ほかの勉強アプリとの同時利用はほぼできない。仲間の機能を StudyReel の中に持つ。

## 1. 決まっていること

- **動画・写真は共有しない。** 録画、サムネイル、タイムラプス、共有カードの画像は、グループには一切流さない
- **チャットは作らない。** 自由に文字を送る機能（グループのトーク、DM、コメント）は持たない。仲間への反応は、用意したスタンプだけ
- **ブロックはある**
- 仕組みは **CloudKit**（Apple の iCloud のデータベース）を使い、自前のサーバーは持たない

## 2. どこまで共有するか

| 情報 | 共有 | 理由・メモ |
|---|---|---|
| ニックネーム | する | アプリの中で決める名前。iCloud の名前や本名は使わない。20文字まで |
| アイコン | する | 用意した絵柄（16種くらい）から選ぶ。写真は使えない |
| いま勉強中かどうか | する | 録画を始めたら「勉強中」、止めたら消える。始めた時刻と経過時間も出す |
| 今日・今週の勉強時間 | する | 保存した記録の時間の合計だけ |
| 連続日数 | する | |
| 受け取ったスタンプ | する（グループの中だけ） | |
| 勉強中の教科・教材 | **しない（初版）** | 教科名・教材名は自分で書ける文字なので、出すと「書き込み」と同じ扱いになる。あとで「用意した教科だけ出す」は検討できる |
| 目標・D-day | **しない（初版）** | 目標の名前は自分で書ける文字。出したい人は今の共有カードで |
| 記録のタイトル・メモ | しない | |
| 過去問の点数 | しない | |
| 動画・写真・サムネイル | **しない（今後も）** | |
| 位置・時刻の細かい履歴 | しない | 「今日の合計」だけで、いつ何分やったかの一覧は出さない |

## 3. できること

### グループ
- 作る：グループ名（20文字まで）を付けて作る。作った人が「オーナー」
- 招待：オーナーが招待リンクを出して、LINE などで送る。リンクから StudyReel が開いて参加する
- 人数：1グループ **20人まで**（案）
- 入れる数：1人が入れるグループは **無料1つ・Pro は5つ**（案）
- 抜ける：いつでも抜けられる
- 外す：オーナーはメンバーを外せる
- オーナーがグループを消すと、グループはなくなる

### グループの画面
- **いま勉強中**：勉強中の仲間を上に並べる。「45分経過」のように出す
- **今日のランキング**／**今週のランキング**：勉強時間の順
- 自分の行には、受け取ったスタンプが並ぶ

### スタンプ
- 用意したものだけ。案：おつかれ／がんばれ／すごい／一緒にやろ／休憩しよ／おめでとう／見てるよ／おやすみ（8種）
- 仲間の行を押して送る。相手の「今日」に付く
- 連打を防ぐ：同じ相手に同じスタンプは1日1回まで。1日に送れるのは合計30回まで（案）
- 通知：スタンプが届いたら通知（設定でオフにできる）

### 通知（すべて設定でオフにできる）
- スタンプが届いた：初期はオン
- 仲間が勉強を始めた：初期は **オフ**（多いとうるさい）

## 4. ブロックと通報

- **ブロック**：グループの画面で仲間の行を長押し → ブロック
  - その人の名前・勉強状況・スタンプが自分の画面に出なくなる
  - その人からのスタンプは届かない（通知も来ない）
  - **できないこと**：CloudKit の共有の仕組み上、ブロックしても相手から自分の勉強状況は見える。相手に見せたくないときは「グループを抜ける」か、オーナーに外してもらう。画面にもそう書く
- **通報**：ニックネームとグループ名は自分で書ける文字なので、不適切なものを通報できるようにする（Apple の審査で求められる）。最初はメールで受け付ける
- ニックネームとグループ名は、よくない言葉を弾く（簡単な NG ワードの一覧）

## 5. CloudKit について

**どういうものか**
Apple が用意しているデータベースです。今の iCloud バックアップは「iCloud Drive にファイルを置く」仕組みで、CloudKit とは別物ですが、同じ iCloud コンテナ（`iCloud.com.ni.StudyTimerAndVideo`）に CloudKit を足して使えます。

**よいところ**
- 自前のサーバーが要らない。ログイン画面も要らない（iCloud にサインインしていれば使える）
- グループのデータはオーナーの iCloud に置かれ、招待した人だけが読める（「共有」という仕組み）。データは小さいので、容量はほぼ使わない
- 開発側の費用は、この規模ならかからない見込み

**気をつけること**
- **iCloud にサインインしていない人は使えない。** その人には「iCloud にサインインすると使えます」と出す
- **iPhone / iPad だけ。** Android の友だちとは組めない（StudyReel 自体が iOS だけなので問題は小さい）
- **リアルタイムではない。** 変化は数秒〜数十秒遅れて届く。「いま勉強中」はおおよそ
- **サーバーで計算できない。** ランキングは各自の端末で計算する。ズルを防ぐ仕組みは弱い（友だち同士のグループなら問題になりにくい）
- **オーナーが抜ける・iCloud をやめると、グループが消える。** データがオーナーの iCloud にあるため。オーナーを引き継ぐ機能は初版では作らない
- **要確認**：共有の参加者には、iCloud の名前が見える場合がある。アプリではニックネームだけを出すが、Apple 側の表示で何が見えるかは試作で確かめる

**データの形（案）**
- グループごとに、オーナーの iCloud に「共有ゾーン」を1つ作る
- その中に、メンバーごとの「状況」（ニックネーム、アイコン、勉強中か、今日・今週の合計、連続日数）と、「スタンプ」を置く
- 各メンバーは自分の「状況」だけを書き換える

## 6. 法律・審査まわり

- **電気通信事業の届出**：利用者同士のメッセージをやり取りさせる機能（チャット、DM）は、総務省への届出が要るとされています。チャットをなくすのはこのためです。用意したスタンプだけなら「いいね」に近い機能ですが、届出が要るかどうかは機能の形で判断されます。公開前に総合通信局の窓口で確認するのが確実です（ここは法律の専門家の確認をおすすめします）
- **App Store の審査（ガイドライン 1.2）**：利用者が書いたもの（ここではニックネームとグループ名）を出すアプリには、不適切な内容を弾く仕組み・通報・ブロック・連絡先が求められる → 4 の内容で満たす想定
- **年齢区分**：App Store Connect の質問に答え直す（ほかの利用者と関わる機能がある、と答えることになる）
- **プライバシーポリシー**：グループで共有する項目（2 の表）と、iCloud に保存されることを書き足す。App のプライバシー表示も見直す
