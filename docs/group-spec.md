# グループ機能 仕様案（たたき台）

YPT やスタディプラスを併用しなくても、StudyReel だけで「仲間と一緒に勉強している感じ」が持てるようにする。
録画中はアプリを開いたままにする必要があるので、ほかの勉強アプリとの同時利用はほぼできない。仲間の機能を StudyReel の中に持つ。

## 1. 決まっていること

- 名前は **「勉強仲間」**（画面では「仲間」）。友達だけでなく、クラスや塾の知り合い程度の人とも組める呼び方にする
- **動画は共有しない。** 録画・タイムラプスの動画そのものは、どこにも流さない
- **写真は、勉強仲間の中でだけ、本人が選んだ1コマだけ。** 自分のタイムラプスの中から、出してもいいと思った瞬間を自分で選ぶ。顔にはモザイクがかかったもの。送らなくても何も困らない
- **資格ごとのグループ（知らない人とつながる場所）には写真を出さない。** 出すのは人数だけ
- **チャットは作らない。** 自由に文字を送る機能（グループのトーク、DM、コメント）は持たない。仲間への反応は、用意したスタンプだけ
- **ブロックはある**
- 仕組みは **CloudKit**（Apple の iCloud のデータベース）を使い、自前のサーバーは持たない

## 2. どこまで共有するか

| 情報 | 共有 | 理由・メモ |

| アイコン | する | 用意した絵柄（16種くらい）から選ぶ。写真は使えない |
| いま勉強中かどうか | する | 録画を始めたら「勉強中」、止めたら消える。始めた時刻と経過時間も出す |

| 連続日数 | する | |
| 受け取ったスタンプ | する（グループの中だけ） | |
| 勉強中の教科・教材 | **しない（初版）** | 教科名・教材名は自分で書ける文字なので、出すと「書き込み」と同じ扱いになる。あとで「用意した教科だけ出す」は検討できる |
| 目標・D-day | **しない（初版）** | 目標の名前は自分で書ける文字。出したい人は今の共有カードで |

## 3. できること

### グループ
- 作る：グループ名（20文字まで）を付けて作る。作った人が「オーナー」
- 招待：オーナーが招待リンクを出して、LINE などで送る。リンクから StudyReel が開く
- **QR コード**：同じ招待リンクを QR コードでも出す。目の前の友だちは iPhone のカメラで読むだけでよい
- **参加は承認制**：リンクや QR から開くと、まず「参加申請」になる。オーナーが許可するまで、グループの中身は見えない
  - 申請には、ニックネームと **4桁の番号**（例：「ゆう #4821」）が出る。番号は自分の設定画面にいつも出ていて、LINE などで「この番号で申請したよ」と伝えられる
  - QR を X などに貼られても、オーナーが許可しない限り入れない
  - 仕組み：CloudKit の共有の「アクセス申請 → オーナーが許可」（iOS 17 以降）が使えるかを試作で確かめる
- 人数：1グループ **20人まで**（案）
- 入れる数：1人が入れるグループは **無料1つ・Pro は5つ**（案）
- 抜ける：いつでも抜けられる
- 外す：オーナーはメンバーを外せる
- オーナーがグループを消すと、グループはなくなる

### グループの画面
- **いま勉強中**：勉強中の仲間を上に並べる。「45分経過」のように出す
- **今日のランキング**／**今週のランキング**：勉強時間の順
- 自分の行には、受け取ったスタンプが並ぶ

### スタンプ
- 用意したものだけ。案：おつかれ／がんばれ／すごい／一緒にやろ／休憩しよ／おめでとう／見てるよ／おやすみ（8種）
- 仲間の行を押して送る。相手の「今日」に付く
- 連打を防ぐ：同じ相手に同じスタンプは1日1回まで。1日に送れるのは合計30回まで（案）
- 通知：スタンプが届いたら通知（設定でオフにできる）

### 通知（すべて設定でオフにできる）
- スタンプが届いた：初期はオン
- 仲間が勉強を始めた：初期は **オフ**（多いとうるさい）

## 4. ブロックと通報

- **ブロック**：グループの画面で仲間の行を長押し → ブロック
  - その人の名前・勉強状況・スタンプが自分の画面に出なくなる
  - その人からのスタンプは届かない（通知も来ない）
  - **できないこと**：CloudKit の共有の仕組み上、ブロックしても相手から自分の勉強状況は見える。相手に見せたくないときは「グループを抜ける」か、オーナーに外してもらう。画面にもそう書く
- **通報**：ニックネームとグループ名は自分で書ける文字なので、不適切なものを通報できるようにする（Apple の審査で求められる）。最初はメールで受け付ける
- ニックネームとグループ名は、よくない言葉を弾く（簡単な NG ワードの一覧）

## 5. CloudKit について

**どういうものか**
Apple が用意しているデータベースです。今の iCloud バックアップは「iCloud Drive にファイルを置く」仕組みで、CloudKit とは別物ですが、同じ iCloud コンテナ（`iCloud.com.ni.StudyTimerAndVideo`）に CloudKit を足して使えます。

**よいところ**
- 自前のサーバーが要らない。ログイン画面も要らない（iCloud にサインインしていれば使える）
- グループのデータはオーナーの iCloud に置かれ、招待した人だけが読める（「共有」という仕組み）。データは小さいので、容量はほぼ使わない
- 開発側の費用は、この規模ならかからない見込み

**気をつけること**
- **iCloud にサインインしていない人は使えない。** その人には「iCloud にサインインすると使えます」と出す
- **iPhone / iPad だけ。** Android の友だちとは組めない（StudyReel 自体が iOS だけなので問題は小さい）
- **リアルタイムではない。** 変化は数秒〜数十秒遅れて届く。「いま勉強中」はおおよそ
- **サーバーで計算できない。** ランキングは各自の端末で計算する。ズルを防ぐ仕組みは弱い（友だち同士のグループなら問題になりにくい）
- **オーナーが抜ける・iCloud をやめると、グループが消える。** データがオーナーの iCloud にあるため。オーナーを引き継ぐ機能は初版では作らない
- **要確認**：共有の参加者には、iCloud の名前が見える場合がある。アプリではニックネームだけを出すが、Apple 側の表示で何が見えるかは試作で確かめる

**データの形（案）**
- グループごとに、オーナーの iCloud に「共有ゾーン」を1つ作る
- その中に、メンバーごとの「状況」（ニックネーム、アイコン、勉強中か、今日・今週の合計、連続日数）と、「スタンプ」を置く
- 各メンバーは自分の「状況」だけを書き換える

## 6. 法律・審査まわり

- **電気通信事業の届出**：利用者同士のメッセージをやり取りさせる機能（チャット、DM）は、総務省への届出が要るとされています。チャットをなくすのはこのためです。用意したスタンプだけなら「いいね」に近い機能ですが、届出が要るかどうかは機能の形で判断されます。公開前に総合通信局の窓口で確認するのが確実です（ここは法律の専門家の確認をおすすめします）
- **App Store の審査（ガイドライン 1.2）**：利用者が書いたもの（ここではニックネームとグループ名）を出すアプリには、不適切な内容を弾く仕組み・通報・ブロック・連絡先が求められる → 4 の内容で満たす想定
- **年齢区分**：App Store Connect の質問に答え直す（ほかの利用者と関わる機能がある、と答えることになる）
- **プライバシーポリシー**：グループで共有する項目（2 の表）と、iCloud に保存されることを書き足す。App のプライバシー表示も見直す

## 7. 追加案（第2段以降）

### 資格ごとのグループ（全体）
- 「TOEIC」「英検」「宅建」などの資格・試験ごとに、だれでも見られる全体のグループを用意する。資格の一覧はこちらで用意する（自分で作れない）
- 出すのは **いま勉強している人数だけ**。例：「TOEIC：いま 23人が勉強中」。名前・アイコン・時間は出さない
- 自分がどの資格で数えられるかは、目標の資格を一覧から選んだときだけ。選ばなければ数えられない
- スタンプ、写真、ランキングはなし（知らない人同士の関わりを作らない）
- 仕組み：CloudKit の **公開データベース**に「いま勉強中（資格、始めた時刻、終わる目安）」だけを書き、人数を数える。名前は書かない
- 容量：開発側の枠を使う。利用者が増えるほど無料枠も増える仕組み。人数を数えるだけのデータなので小さい（正確な上限は Apple のドキュメントで確認）

### 写真の共有（勉強仲間だけ・本人が選んだときだけ）
- **資格ごとのグループでは出さない**
- 勉強を保存したあと、タイムラプスを動かして「この瞬間なら出してもいい」という1コマを自分で選び、仲間に見せる
- 出せるのはその1コマだけ。顔の自動モザイクをかけたもの。カメラロールの写真は選べない。送らないのが初期の状態
- **24時間で消える**（決定）
- 1人1日1枚まで
- 通報（オーナーにも開発者にも）、オーナーによる削除と外す操作、ブロックした人の写真は出ない

#### 変な写真への対策（何重かにする）
1. **撮れるものを絞る**：StudyReel で録画したタイムラプスの1コマだけ。カメラロール・ネットの画像は選べない
2. **自動で見分ける**：Apple の「センシティブなコンテンツの分析」（SensitiveContentAnalysis）で、端末の中で裸などの画像を見分ける。見つかったら、送る側では送れない、受け取る側では出さない（ぼかさずに出さないだけ）
   - iPhone の設定「センシティブな内容の警告」を本人がオンにしているときだけ結果が返る（子どものアカウントでは初めからオン）。アプリの側でオンにはできない（Apple がそう作っている）ので、これだけには頼らない
   - 使うには Apple への申請（エンタイトルメント）が要る
   - アプリ単位で必ず見分けたくなったら、判定用の AI モデルをアプリに入れる方法がある。精度と誤判定の調整を自分で持つことになるので、初版では入れない
3. **受け取る側を守る**：写真はぼかさずにそのまま出す（UX を優先、決定）。「写真を受け取らない」は選べる
4. **数を絞る**：1人1日1枚、24時間で消える、グループの写真は初期オフ
5. **すぐ外せる**：オーナーは写真を消せる、その人を外せる

#### 証拠と開発者の対応
- CloudKit の共有データは **開発者からも見えない**。開発者があとから確かめたり消したりはできない
- そのため **通報すると、通報した人の端末から、写真・送った人のニックネームと番号・CloudKit の利用者番号・グループ・日時を開発者に送る**。24時間で消えても、通報された分は残る
- **最終的な判断は開発者がする**（決定）。中身を見て、悪質なら **その人を写真の機能から締め出す**
  - 締め出しには CloudKit がアプリごとに振る利用者番号を使う（4桁の番号は人と重なることがあるので使わない）
  - 公開データベースに「写真を送れない利用者」の一覧を置き、アプリが送る前に見る。一覧は CloudKit のコンソールから開発者が編集する
- **開発者に分かるのはアプリごとの利用者番号だけで、Apple ID やメールアドレスなど、その人が誰かまでは分からない**。警察が関わる件は、警察から Apple に照会する流れになる
- 通報で写真と番号を受け取ることは、プライバシーポリシーに書く
- 児童の性的な画像のような重い内容は、警察・通報窓口に届ける。対応の手順をあらかじめ決めておく

#### 未成年の保護（もう一段）
- iOS 26 からの Apple の「年齢の範囲」（Declared Age Range）で、本人や保護者が許した範囲で18歳未満かどうかが分かる
- **18歳未満と分かったら、写真の送受信は初期オフ**（決定）。本人がオンにできるかどうか（保護者の許可を要るようにするか）は試作で確かめてから決める
- **QR コードを X などに貼られたときの備え**：公開されると知らない人も入れて、その人にも写真が見えてしまうので
  - 写真の共有は **グループごとにオーナーがオン・オフ**する。初期はオフ。知り合いだけのグループならオンにする
  - 送る前に「この写真は 6人に見えます」と、見える人数を出す
  - オーナーは招待リンク（QR）を作り直せる。古い QR では入れなくなる。入ってしまった人はオーナーが外せる（作り直しが CloudKit でどこまでできるかは試作で確かめる）
- 容量：オーナーの iCloud に置かれる。1枚200KBくらい、20人が1日1枚で1日4MB程度。24時間で消すのでほとんど使わない
- **先に確認すること**：決まったメンバーに写真を届けるのは、グループトークで画像を送るのに近い。チャットと同じく電気通信事業の届出が要るかどうか、総合通信局で確認してから入れる。審査では利用者が上げる画像への対策（通報・削除・ブロック）を見られる

### フォロー・フォロワー
- **今は入れない**
- 知らない人とつながる仕組みになり、公開プロフィール、検索、嫌がらせ対策、未成年の保護まで必要になる
- 勉強仲間（QR で招待）と資格ごとの人数で、「仲間がいる感じ」はほぼ出せる。必要になってから考える
