# 保護者・塾に共有（見守り）

1.9 で入れる。アプリの中では「保護者・塾に共有」、コードでは `WatchCloud`（Utilities/Buddies/WatchCloud.swift）と `WatchView`（Views/Buddies/WatchView.swift）。
勉強仲間と同じく CloudKit のゾーン共有を使い、新しいサーバーは持たない。

## 見せるもの・見せないもの

| 見せる | 見せない |
| --- | --- |
| いま勉強中かどうか、今日・今週の勉強時間、今週の曜日ごとの時間、連続日数、最後に勉強した日、ニックネームと4桁の番号 | 動画、写真、メモ、記録のタイトル、教科、勉強仲間の中身 |

曜日ごとの時間と最後に勉強した日は、見守りのゾーンにだけ書く（勉強仲間のグループには書かない）。

## しくみ

設計案（子が QR を見せ、親が申請し、子が許可する）から向きを変えた。**見る人が QR を見せ、見せる人が読んで自分で始める。**
こうすると、始める操作がいつも見せる人の端末になり、許可の画面が1つ減る。先生が生徒30人の QR を1人ずつ読む必要もない。

1. 見る人（保護者・先生）が「QR コードを作る」。公開データベースの `BuddyWatchCode`（`watch-<トークン>`）に、種類（`family` / `school`）、呼び名またはクラス名、塾の名前、見る人の利用者番号を置く
2. 見せる人（子・生徒）が QR（`studyreel://watch/join?t=<トークン>`）を iPhone のカメラで読む → StudyReel が開き、だれに何を見せるかを確かめて「見せる」を押す
3. 見せる人のアプリが、自分の iCloud に `watch-` で始まるゾーンを作る。中は `watch`（BuddyWatch：だれに見せているか）と自分の `member-…`。ゾーンごと CKShare で共有し、参加者は見る人1人だけ
4. 公開データベースに申し出 `BuddyWatchOffer`（`offer-<トークン>-<見せる人>`）を書く。共有の URL とゾーンの名前が入っている
5. 見る人のアプリが申し出を見つける →「受け取る」で共有に入る。「断る」と `BuddyJoinDenial`（`no-offer-…`、`zone` にゾーン名）を書き、見せる人のアプリがゾーンを消す
6. 受け取られたら、見せる人のアプリが申し出を消す

- 見せる人1人・見る人1人ごとにゾーンが分かれる。両親に見せるならゾーンは2つ。生徒どうし、保護者どうしは見えない
- 見せる人はいつでも「やめる」（ゾーンを消す）。見せている間はホームに「保護者に勉強状況を共有中」などと必ず出る（消せない）
- 見る人が「見守りをやめる」「外す」と、断りと同じ `BuddyJoinDenial` を書いてから共有を抜ける。見せる人のアプリは、自分のゾーンあての断りを見つけたらゾーンを消す
- スタンプは見る人から見せる人へ「がんばれ」「おつかれ」「すごい」だけ（1日1回ずつ）

## 保護者

- 設定 →「保護者・塾に共有」、または勉強仲間の画面から開く
- 呼び名（例：お母さん）を入れて QR を作る。子の画面には「『お母さん』に、勉強時間を見せますか？」と出る
- 子ごとのカード：いま勉強中、今日・今週・連続日数、今週の曜日ごとの棒グラフ、スタンプ
- 通知：「今日の勉強を始めました」（初めはオフ）、「今週の合計」（日曜18時すぎ、初めはオン）
  - CloudKit の静かなプッシュで目を覚ましたときに出す。日曜の夜に子が勉強しないと、プッシュが来ないので出ないことがある
- お金：無料。Pro のファミリー共有は App Store Connect で各サブスクごとにオンにする（**一度オンにすると戻せない**ので、まだオンにしていない）

## 塾

- 先生は塾コードを入れるとクラスを作れる（10クラスまで、1クラスの人数は塾コードの `maxStudents`、なければ50人）
- クラスの画面：申し出（受け取る・断る）、3日以上勉強していない人、今週の勉強時間の多い順、CSV の書き出し（Excel 用に BOM つき UTF-8）、スタンプ、外す、クラスを閉じる
- 生徒の画面には「『○○塾 中3 英語』の先生に、勉強時間を見せますか？」と出る

### 塾コードの発行（開発者）

CloudKit Console → Production → Records → Public → `BuddySchoolCode` → New Record

| 項目 | 値 |
| --- | --- |
| Record Name | `school-<コード>`（コードは英小文字と数字で12文字以上。推測されないもの） |
| `schoolName` | 塾の名前（生徒の画面に出る） |
| `maxStudents` | 1クラスの人数の上限（空なら50） |
| `expiresAt` | 契約の終わり（空なら期限なし） |
| `note` | 契約のメモ（アプリには出ない） |

- 先生にはコードだけを伝える。期限を過ぎる・レコードを消すと、新しいクラスを作れなくなり、先生の画面に「期限が切れています」と出る（すでに受け取った生徒の共有は残る。止めるときは生徒か先生が操作する）
- 塾コードの確認はアプリの中で行うので、改造したアプリなら通り抜けられる。見られるのは自分から「見せる」を押した生徒の勉強時間だけなので、害は小さいと判断した

### お金（まだ決めること）

- 塾に直接売る（請求書・振込）。Apple のガイドライン 3.1.3(c)（Enterprise Services）に当てはまる前提
- 価格の案：生徒1人 月 ¥300。最初の1塾は無料で試してもらう
- 契約書・請求書、生徒の勉強時間を塾に見せることの説明（生徒と保護者向け）を用意する

## 出す前にやること

1. `[cloudkit-schema]` で開発環境にスキーマを入れ、CloudKit Console で本番に反映（docs/buddies-setup.md）
2. プライバシーポリシー（company-web）に見守りを足す：見る人に渡るもの、塾コード、公開データベースに置くもの（コード・申し出）
3. TestFlight で2台・2アカウント：保護者（QR を作る → 子が読む → 受け取る → スタンプ → 子がやめる）と、塾（塾コード → クラス → 生徒2人 → CSV）
4. 審査メモに、見守りの説明と、塾コードのテスト用コードを書く
